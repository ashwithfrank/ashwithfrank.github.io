Overview

AFDrive turns any old Android phone into a private cloud storage server. Instead of paying for cloud storage or trusting a third party with your files, AFDrive runs entirely on-device via Termux, serving a clean web dashboard to any other device on the same Wi-Fi network — laptop, tablet, or another phone.

The backend is a Flask + SQLite app; the frontend is vanilla HTML, CSS, and JavaScript — no Node.js, no build step, no heavy frameworks. Files stay exactly where they are on the phone's filesystem; the database only ever holds account credentials, never file data, so the listing you see is always read live and can never drift out of sync with what's actually on disk.

How It Runs

The whole setup lives on the phone itself — install Termux, install Python, clone the repo, and start the Flask server. Any device on the same network can then log in through a browser at the phone's local IP address.

Phone (Termux)
  └─ python app.py  →  0.0.0.0:5000
                          │
      same Wi-Fi network │
                          ▼
   Laptop / Tablet / Phone  →  http://PHONE_IP:5000

Core Features

Full File Manager

Browse folders, breadcrumb navigation, create/rename/delete, sort by name, size, or date, and recursive search.

Drag & Drop Upload

Multi-file upload with a live progress bar and duplicate-safe naming — no file ever gets silently overwritten.

Inline Preview

Images and text files preview directly in the browser; PDFs open in an embedded viewer.

Traversal-Safe by Design

Every filesystem path is resolved through a single safe-join function that blocks path traversal, absolute paths, and symlink escapes.

Light / Dark Mode

Mobile-first responsive UI with a theme toggle that's remembered across sessions via localStorage.

Login-Protected

Hashed passwords, protected routes, and generic auth errors that reveal nothing about valid usernames.

Security Notes

  • No plaintext passwords — hashed with Werkzeug's generate_password_hash.
  • Path safety — every upload, download, rename, and delete is resolved through fs_utils.safe_join_storage() before touching disk.
  • Streamed transfers — downloads use Flask's send_file with range support, so large files never load fully into RAM.
  • Debug mode off by default — has to be explicitly enabled, and never in production.
  • Security headers set on every response — X-Content-Type-Options, X-Frame-Options, and a restrictive Content-Security-Policy.

Built for trusted local-network use — not hardened for direct exposure to the public internet without a VPN or reverse proxy in front of it.

What I Learned

This project pushed me past "make it work" into "make it safe by default" — every path that touches the filesystem funnels through one audited function, which made the security model much easier to reason about than scattering checks across routes. Designing around a phone as the server (rather than a always-on machine) also meant thinking hard about resilience: sessions, wake locks, and what happens when Termux gets killed in the background.
